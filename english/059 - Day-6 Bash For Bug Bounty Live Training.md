**Core syllabus delivered today:**
- **Parameter** = *"any entity that stores values."* Shell parameters exist to **store data and later reference it inside scripts.** Three kinds: **VARIABLE · POSITIONAL parameter · SPECIAL parameter** (today = variables; the other two deferred).
- **Variable** = *"a parameter whose VALUE you can MANUALLY CHANGE."* Mental model = **labeled boxes**: assigning (`STUDENT=Nitesh`) = putting data **INTO** the box; referencing (`echo ${STUDENT}`) = pulling data **BACK OUT** to use — his exact arrows/diagrams on the whiteboard.
- **Assignment syntax law: NO spaces around `=`.** Reference syntax: **`${NAME}` = the "right/professional" way** (`$NAME` works for reads, but **advanced parameter-expansion features ONLY function with `${…}`** — that's why he drills the braces).
- **Parameter expansion, defined operationally** (his words): when the shell meets `${STUDENT}`, it **finds the parameter named `STUDENT`, fetches its ENTIRE stored value, and REPLACES the `${STUDENT}` text with it** before the command runs. `echo ${STUDENT}` literally *becomes* `echo Nitesh`.
- **Why variables = the automation payoff:** a value used in 25 places of a 100-line (or 2000-line) script — change it ONCE at the definition and every reference updates automatically. Direct literals = 25 manual edits.
- **Persistence:** variables are **TEMPORARY — they die at logout**; permanence = entries in the **profile file** (covered in his Linux series — or a dedicated video on request via the group).
- **Naming rules (all four live-proven on Kali today):** (1) no leading special character (`@STUDENT=…` → *command not found*), (2) no leading digit (`4STUDENT=…` fails), (3) leading **underscore is legal** (`_STUDENT=Sachin` works), (4) **reserved words are off-limits** as variable names (can't define `echo=…`).
- **System-defined = environment variables**: *"an environment variable is a DYNAMIC NAME-VALUE which may be used by ONE OR MORE programs running."* The OS pre-seeds dozens per login; every user's session = its own environment (company logins with pre-loaded permissions/welcome-messages are this exact mechanism). **Social convention: env/system vars in ALL-CAPS, user vars in lowercase — purely a readability pact between programmers, not a shell rule.**
