1. **Today's three deliverables (as framed):** (a) **globbing** — step-3's fourth-and-final expansion stage; (b) **step-4 quote removal**; (c) **step-5 redirection** — completing the five-step "how bash processes the command line" arc that started the whole course. 2. **GLOBBING (a.k.a. filename expansion)** — origin: the **`glob`** program in Bell Labs Unix (1969–1975); definition given verbatim on-screen: *"the glob program was a program that would replace text containing special pattern symbols with a list of filenames that matches those patterns."* It runs **only on words** (post-tokenization) and only when the pattern chars appear **UNQUOTED** in them. The three glob characters: **`*`**, **`?`**, **`[ ]`**.
3. **Verified glob semantics from the lab** (home dir; created: `file1.txt…file5.txt`, `filea.txt`, `ABC`, `abc`, `file12th`, `ab`):
   - `ls *` → everything in CWD (Desktop/Documents/Downloads/…). **Star = any run of any chars, length-independent.**
   - `ls *.txt` → file1–5.txt (etc.); `ls *.pdf` → nothing (no match).
   - `ls file*` → file1–5.txt + filea.txt + file12th (**star matches even extra runs**); `ls file1*` → file1.txt **and** file12th (2 files).
   - `ls file?.txt` → file1–5.txt + filea.txt only — **`?` = exactly one character**; not abc/12th. Question-mark count = exact length; "neither more nor less."
   - `ls file???.txt`-family → only ABC & abc (3-char names).
   - `ls file[abc].txt` → only filea.txt (one char from the given set). `[1a]` → file1.txt + filea.txt. **Brackets = length-specific single character from an explicit set** — "like ?, but restricted to the listed characters."
   - Chained brackets = positions: `[ab][ab]`-style matched `ab`; three-char `[abc]`-scoped lookups matched `abc` (lowercase only — **case-sensitive**: capital ABC needs capital entries).
   - **Ranges inside brackets**: `[a-q]`, `[0-9]` — must be a proper sequence ("without sequence it won't work"); combined with the star it caught `file12th`.
   - **Works on paths, not just CWD:** `ls /*` listed everything under `/` — "this is the power of globbing."
4. **STEP-4: QUOTE REMOVAL** — quoting (Day-3) = removing a character's special meaning, via three quotes: **backslash, single quote, double quote**. Once quoting has neutralized meaning, the quotes themselves are redundant → step-4 deletes them, **but ONLY under two conditions** (his on-screen definition): *"during quote removal, the shell removes all unquoted backslashes, single quotes, and double-quote characters that did not result from shell expansion."* — i.e., (1) the quote chars must be **unquoted**; (2) they must NOT be **output of an expansion**.
   - Demo 1: `echo \$HOME` → prints `$HOME` (backslash was unquoted & hand-typed → removed).
   - Demo 2: `echo '\$HOME'` → prints `\$HOME` (single quotes removed; the backslash was **quoted by them** → stays).
   - Demo 3: `name="C:\Users\sachin\documents"` then `echo $name` → **C:\Users\sachin\documents** — the backslashes SURVIVE because they arrived *as expansion output* (condition 2 fails). (His live run wobbled through a goofed `echo \$name` variant that printed `$name` literally — he then lands the two-condition explanation; preserved.)
