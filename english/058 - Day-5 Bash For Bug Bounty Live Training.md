- **Step-2 curriculum (command identification), as taught:** commands come in exactly **two kinds — SIMPLE vs COMPOUND**. **Simple commands** = your daily `echo`, `ifconfig`, etc. The interpreter treats **WORD-1 = the command NAME**; all remaining space-separated words = that command's **arguments/inputs**. **Every simple command terminates at a CONTROL OPERATOR**; if you didn't type one, the **invisible trailing NEWLINE at the end of every command line** is your terminator — that's why a lone `echo 1 2 3` still ends cleanly. Control operator roll-call re-read aloud: `newline  |  ||  &  &&  ;  ;;  ;&  ;;&  |&  (  )`.
- **The three escalation examples, verbatim-decoded:**
  1. **`echo 1 2 3 <no semicolon> echo A B C D`-style run-on** — tokenisation counts ~7 spaces (all metacharacters but NOT control/redirection operators) ⇒ the second "echo …" word-sequence is INHALED as mere arguments; **one single simple command**. The lesson: *spaces split words, not commands*.
  2. **`echo $name > out.txt`** — 3 words + 1 operator, but the operator is REDIRECTION (`>`), not control ⇒ **still ONE simple command**; the redirection operator is absorbed as part of that simple command and **executes its task LAST** (his detail: "jo sabse last mein apna task perform karta hai"). `$name`'s dollar is *not* a metacharacter — it gets NO say in step 1; its turn comes in step 3.
  3. **`echo 1 2 3 ; echo A B C`** — at last a `;` = control operator ⇒ line cleaves into **TWO simple commands**, each terminated independently.
- **Compound commands:** "each compound command STARTS with a RESERVED word and is TERMINATED by the CORRESPONDING reserved word"; reserved words = "words that HAVE a special MEANING to bash." Demonstrated with the **`if … ; then … fi`** skeleton (`if <condition>; then <commands> fi` — "hello world" as the embedded simple command). Purpose: **conditions & logic** — "compound commands = bash's PROGRAMMING itself"; structurally = "a COMBINATION of compound + simple commands." He parks the `[ … ]`/test syntax explicitly for next class ("abhi itni zaroorat nahi").
- **Step-3 map (expansion)** — *"once the shell has completed tokenisation, it performs SHELL-expansion ON THE WORDS in the command line."* (Expansion never touches operators.) Four stages, and **seven named expansion types**:
  - **Stage 1 — BRACE expansion**
  - **Stage 2 — PARAMETER expansion, ARITHMETIC expansion, COMMAND SUBSTITUTION, TILDE expansion** (four co-equal citizens)
  - **Stage 3 — WORD SPLITTING**; **Stage 4 — GLOBBING**.
- **Note 1 (stage order trumps position):** "expansions in earlier stages are performed FIRST — irrespective of where they sit in the line."
