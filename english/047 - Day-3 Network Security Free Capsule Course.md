### Translator's notes (garble / reconstructions of consequence)

- **Packets vs frames:** data chopped into chunks per the OSI story; each layer adds info (headers) going down, strips it going up. **Frame → packet** = the moment IP addressing info gets added (the room's quiz answer). Envelope-in-envelope picture; the animal-picture reassembly diagram (ASR: "goat/billi").
- **Headers taught:** **TTL** (per-hop decrement — demo 5→4→3…, packet discarded at 0 so lost packets never crowd the network forever); **checksum** (integrity — detects in-transit change/corruption); **source address** (needed so replies can be sent back) vs **destination** (obviously needed).
- **TCP revision + close-sequence:** integrity/reliability guaranteed at the cost of slowness; SYN → SYN+ACK → ACK, data, then the **two-sided FIN close** (Alice FINs, Bob ACKs + sends his own FIN, final ACK) — plus the room's flag-copying quiz bits (garbled).
- **Ports:** introduced here for the first time (deliberately deferred last class): house address = IP, **room/gate number = port**; computer has ~65,535 total ports (the cut sentence) — chunk-2's remaining garble covers ranges: well-known/reserved (0–1024) with the famous assignments — **FTP 20/21, SSH 22, HTTP 80, HTTPS 443, SMB 445, RDP 3389** (odd-number sequence 150/25/20 → those), MySQL-ish 3306; others assigned as applications come.
- **Port forwarding:** NAT handles inside→outside by noting IP+port per request; **outside→inside needs a manual router entry**: "public IP : port 80 → this internal device : port" (home routers expose it under security/forwarding config; his own router oddly lacks the option). Demo: **ngrok** — downloads latest, hosts a file containing "hello" on port 80, accessible in-network via his IP; then pastes the ngrok web address → reachable from anywhere in the world. **ngrok limits:** session-limited, **link changes every restart**, dies on heavy traffic → prefer router-side forwarding (public IP).
- **Firewall:** soldier-guard analogy; inspects source/destination/port/protocol; can pattern-block floods (many packets, all ports) → keep the server from overloading/crashing; **stateful = judges whole connections (blocks the misbehaving device)**, **stateless = judges individual packets (drops the bad packet only)**; OSI-layer question followed (application etc., garbled answers).
- **VPN:** Virtual Private Network; connects two far networks (India↔Africa) as if one LAN; **TryHackMe is the live example** — OpenVPN config file → you join their network and reach their devices; same for certification exams.
